Inspect the execution boundarySix typed sandbox actions

Raphael coordinates the workflow; the separate Ignis executor runs sandbox operations through a typed interface. This is a bounded workflow, not unrestricted shell access.

  • create_sandbox
  • deploy_revision
  • observe_failure
  • run_validation
  • finalize_result
  • destroy_sandbox

Configured live execution and recorded fixture modes are distinct. A recorded result is not proof that a real deployment was tested.

Planned / custom context + tool loopA separate roadmap direction. Not available as shown.

The planned custom harness would gather relevant evidence into a bounded working context, choose permitted tools, and update its hypotheses from the results. The execution strategy is not final.

  1. Build context
  2. Reason
  3. Choose a permitted tool
  4. Execute
  5. Observe and update
  6. Validate or stop

Existing structured run state and bounded patch retries are current foundations. The broader custom harness is planned; it is not the workflow depicted above.
